# SOS v0.10.3 Release Notes

Date: 2026-05-20
Tracker: https://github.com/Mumega-com/sos/issues/147

## Summary

SOS v0.10.3 is the first public-kernel release candidate after the OSS
extraction and Public 10 cleanup train. It makes the repository usable without
hidden Mumega context: public boundary gates are in CI, the local profile can
prove a two-agent bus flow, core docs explain what is working today, and
private host overlays are kept outside the reusable kernel.

This remains alpha software. The release is intended for developers and
operators who are comfortable running Python services, Redis, and MCP tooling.

## What Works In This Release

- Local public profile: Redis, bus bridge, MCP server, and Squad task service.
- Two-agent bus smoke: `alpha` sends to `bravo`, and `bravo` reads the message
  from its project-scoped inbox.
- Squad smoke: create, claim, and complete a task through the local profile.
- Mirror-disabled mode: bus, inbox, peers, status, and task flows run without
  Mirror.
- Optional host profile contract for OpenClaw, Hermes, scripts, and private
  overlays.
- Operator snapshot command: `sos operator`.
- Public release gates for private-path boundary, security docs,
  plugin-boundary docs, version metadata, and pytest collection.

## Major Changes Since v0.10.0

- Public OSS boundary cleanup for SOS, Mirror, and Inkwell.
- Public local quickstart and `sos local` helper commands.
- Security model docs and CI guard.
- Plugin/profile boundary docs, adapter sketch, and CI guard.
- `sos operator` runbook loop and working-today ledger.
- First MCP tool maintainability split: status tools moved into
  `sos.mcp.tools.status`.
- Version metadata aligned at `0.10.3`.

## Upgrade Notes

- The Python package remains named `mumega` for this release, with `sos` as the
  primary CLI entry point.
- Mirror is optional. Memory tools need a configured Mirror deployment.
- Private Mumega runtime code belongs in host overlays such as
  `mumega_sos_addons`, not in the public SOS kernel.
