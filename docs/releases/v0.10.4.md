# SOS v0.10.4 Release Notes

Date: 2026-05-21
Tracker: https://github.com/Mumega-com/sos/issues/147

## Summary

SOS v0.10.4 publishes the S110-S114 public-kernel extraction work to the public
repository. The release tightens the reusable kernel around generic MCP
transport, public tool policy, registry-client boundaries, hosted-service
overlay seams, and a fresh-clone operator proof.

This remains alpha software for developers and operators who are comfortable
with Python services, Redis, and MCP tooling.

## What Works In This Release

- Fresh public clone install from GitHub `main`.
- `sos`/`mumega` CLI version and doctor commands.
- MCP gateway health plus public `send`, `inbox`, `broadcast`, `peers`,
  `status`, and Mirror-optional `recall` tools.
- Empty-registry behavior for unregistered kernels.
- Dashboard mesh/operator reads through the public `RegistryClient`, without
  direct imports from registry service internals.
- Host-owned service map overlays through `SOS_SERVICE_MAP_SVG_PATH`.
- Public release CI for boundary, security docs, plugin docs, version metadata,
  and full pytest collection.

## Major Changes Since v0.10.3

- Split MCP public-kernel transport, tool registry, and tool policy into
  generic modules.
- Removed stale customer MCP catalogues from public SOS.
- Added `scripts/prove_public_operator_install.sh` and
  `docs/operator-first-run.md`.
- Added S112 hosted-service extraction inventory and public dashboard service
  map boundary tests.
- Added typed `AgentCard` reads to `RegistryClient` and routed dashboard mesh
  reads through that HTTP client.
- Removed the stale private Mumega post-index test from public collection.
- Kept provider SDKs optional by making Gemini, Grok, and OpenAI SDK imports
  lazy.
- Restored dev-only `fakeredis` and `scipy` so fresh public dev installs can
  collect the public test suite.
- Version metadata aligned at `0.10.4`.

## Upgrade Notes

- The Python package remains named `mumega` for this release, with `sos` as the
  primary CLI entry point.
- Provider SDKs remain optional. Install provider extras only for the providers
  a host actually uses.
- Mirror is optional. Memory tools need a configured Mirror deployment.
- Private Mumega runtime code belongs in host overlays such as
  `mumega_sos_addons`, not in the public SOS kernel.
