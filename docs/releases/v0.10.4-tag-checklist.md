# v0.10.4 Tag Checklist

Use this checklist immediately before creating `v0.10.4`.

## Required State

- `pyproject.toml` version is `0.10.4`.
- `sos.__version__`, CLI version output, installed package metadata, and
  `CHANGELOG.md` all agree on `0.10.4`.
- `LICENSE` is MIT and complete.
- `CONTRIBUTING.md` explains the public/private boundary and MIT contribution
  posture.
- Release notes exist at `docs/releases/v0.10.4.md`.
- Known release gaps are linked from the release notes and GitHub tracker.
- The branch is merged to `main`.
- GitHub release-gate workflow passes on `main`.

## Local Verification

Run from a clean checkout:

```bash
python3 -m compileall sos scripts tests
uv run --extra dev pytest tests/test_version_metadata.py tests/cli/test_local_profile.py tests/cli/test_operator.py tests/mcp/test_status_tools.py tests/mcp/test_mcp_tool_rbac.py
uv run --extra dev python scripts/check_public_release_boundary.py --show-ok
uv run --extra dev python scripts/check_public_security_docs.py
uv run --extra dev python scripts/check_plugin_boundary_docs.py
pytest --collect-only -q
SOS_PUBLIC_REPO_URL=git@github.com:Mumega-com/sos.git SOS_PUBLIC_REF=main scripts/prove_public_operator_install.sh
scripts/sos-local-dev.sh up
scripts/sos-local-dev.sh doctor
scripts/sos-local-dev.sh down
```

Expected quickstart proof:

- Redis OK.
- Bus bridge `/health` OK.
- MCP `/health` OK.
- Squad `/health` OK.
- `alpha` to `bravo` send/inbox OK.
- task create/claim/complete OK.
- Mirror optional/disabled OK.

## Tag Command

After the PR is merged and `main` is clean:

```bash
git switch main
git pull --ff-only origin main
git tag -a v0.10.4 -m "SOS v0.10.4"
git push origin v0.10.4
```

## Do Not Tag If

- The boundary checker reports private/add-on paths in public main.
- Version metadata is out of sync.
- The fresh public operator proof cannot prove MCP health, empty registry,
  send/inbox, broadcast, peers, and status.
- The local doctor cannot prove the two-agent send/inbox flow.
- Known gaps are only in private memory and not visible in GitHub issues or
  release docs.
